A production app does not need one cloud; it needs the right cloud for each job, and each of the big three has one area where its permanent free allowance is hard to beat: Azure for databases, Google for web apps, AWS for serverless building blocks.

I compared the always-free allowances on each cloud as of October 2026, then checked whether anyone else matches them. I left out sign-up credits and trials: every provider has them, and they expire. Only permanent allowances can sit under a production app, so those are what this post covers.

Azure: a free SQL Server database, or ten

Azure's standout freebie is a real managed SQL database that stays free for the life of your subscription. Each subscription can have up to 10 General Purpose databases, and every one gets 100,000 vCore seconds of serverless compute, 32 GB of data and 32 GB of backup storage free each month (Microsoft Learn).

  • Permanent: the offer works on any subscription type and stays free as long as the subscription is active (Azure SQL blog).
  • Production-ready: it is a full General Purpose database, so growing past the free amount takes a few clicks rather than a migration (Azure SQL devblog).
  • How far the compute goes: 100,000 vCore seconds is about 28 hours of one vCore per database per month (my arithmetic), or a million vCore seconds across all ten.
  • Catch 1, billing: if you keep a database online past the monthly free amount, the overage is billed at standard serverless rates, so choose to let it pause instead if you want a hard stop.
  • Catch 2, region: all your free databases in a subscription share one region, picked once and fixed.
  • Catch 3, features: a free database cannot join an elastic pool or a failover group.

Azure also reportedly added a free SQL Managed Instance in May 2025, with 720 vCore hours and 64 GB of storage per month (summary).

Google Cloud: ship a web app without the paperwork

Google's best freebie is Cloud Run: hand it a container and you get a public HTTPS service that scales to zero and costs nothing inside the free quota. The always-free monthly quota is 2 million requests, 180,000 vCPU-seconds and 360,000 GiB-seconds of memory, applied across all your Cloud Run services (Cloudchipr). Custom domains with HTTPS are free too (Niche e-Lab).

Cloud Run pairs naturally with Google's other free pieces:

  • Firestore: a NoSQL database for app data, with 1 GiB of storage and daily caps of 50,000 reads, 20,000 writes and 20,000 deletes.
  • Firebase Auth: ready-made login for your app: email and password, Google, Apple and other providers, plus login tokens your backend can verify. Free for up to 50,000 monthly active users. Optional multi-factor authentication (MFA) by SMS code needs an Identity Platform upgrade, which caps free-plan projects at 3,000 daily active users.
  • BigQuery: quick SQL scans of large datasets, with 1 TiB of queries and 10 GiB of storage per month.
  • Compute Engine: a small virtual server that can run a bot or task that stays on all the time. One e2-micro VM per month, in selected US regions only.
  • Pub/Sub: messaging between app components, 10 GiB per month; Cloud Build: automated builds and deploys, 120 build minutes per day.

AWS: a pantry of serverless building blocks

AWS has no single standout freebie; what it gives away permanently is a set of small serverless building blocks. More than 30 services are always free within monthly limits (AWS Free Tier FAQs). The ones that matter for a production app:

  • Lambda: runs your code only when something triggers it, like a web request or file upload, 1 million requests per month.
  • SQS: a waiting line for jobs: one part of your app drops in a message and another picks it up when ready, 1 million requests per month (community list).
  • SNS: sends one message to many receivers at once, such as email, text messages or other services, 1 million publishes per month (community list).
  • DynamoDB: a fast NoSQL database, 25 GB of storage (2026 guide).

The catch: AWS's managed relational databases, RDS and Aurora, are not part of the always-free allowance. Keep your relational data on Azure's free database and let AWS handle the plumbing.

AWS is the natural home for the glue: queues, functions and events that connect the other pieces. It is also the vocabulary that crypto and fintech job listings keep naming.

Is anyone else giving away a SQL database?

Among the big three, only Azure does, but it is not alone in the wider industry. Two others I found:

  • Oracle Cloud: the Always Free tier includes two Autonomous Databases, each with 1 OCPU and 20 GB of storage, with no time limit (Oracle). They cannot be backed up or restored unless you upgrade to a paid instance (Oracle docs). Oracle also gives away up to four Arm cores and 24 GB of RAM as always-free compute (CNX Software).
  • Cloudflare: D1 is a serverless SQLite database on the free Workers plan, with 5 GB of storage, 5 million rows read per day and 100,000 rows written per day (Cloudflare). Since September 1, 2026, queries fail once you pass the daily limits (changelog).

So "nobody else gives you a free SQL database" is not quite true. What is true is that Azure's offer is the largest I found: ten databases on the SQL Server engine at 32 GB each, for as long as you keep the subscription. Oracle's is two databases at 20 GB, and Cloudflare's is 5 GB total on SQLite.

I did not survey every provider. Platforms like DigitalOcean, Vercel, Supabase and Neon are outside this comparison.

Mix and match: the right cloud for the right job

Build a production app from the free allowances that fit each part of it, and set a budget alert before you depend on any of them.

  • Free is not the same as safe. Azure overage bills unless you let the database pause. Google quotas are capped per billing account or project. Cloudflare simply stops your queries.
  • Allowances change. Google itself says always-free offers are subject to change, so recheck the official page before you commit to a design.
  • Region matters. Azure's free databases lock to one region, and Google's free VM runs only in selected US regions.

Which one for what:

  • Relational database: Azure.
  • Web app or API hosting: Google Cloud Run.
  • Queues, functions and event glue: AWS.
  • A tiny SQL database at the edge: Cloudflare D1.

Nothing stops you from mixing them: a production app can keep its data on one cloud, serve its web tier from another, and run its background jobs on a third.
